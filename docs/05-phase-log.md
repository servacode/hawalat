## المرحلة 0 — الأساسات (Foundations)

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** بيئة تعمل بأمر واحد: Django + Next.js + Docker + CI + أدوات جودة.

### ما أُنجز
- Backend: Django 5.1 + DRF + Channels + Celery، إعدادات مقسّمة (base/dev/prod)، تطبيق `core`، نقطة `/api/health/`، اختبار دخاني.
- Frontend: Next.js 15 + TS + Tailwind 4، عربي/RTL، خط Tajawal، نواة طبقة التوكِنز بألوان الهوية.
- بنية: docker-compose (db+redis+web+worker+frontend)، Dockerfiles، Makefile، pre-commit، GitHub Actions CI، `.env.example` يخدم الوضعين.

## المرحلة 1 — النظام المركزي (Centralized Systems) ⭐

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** طبقة التوكِنز + مكتبة المكوّنات + صفحة عرض؛ وفي الباكند: Tenancy + RBAC + هيكل محرك القيود + Mixins.

### ما أُنجز

**Backend:**
- `apps/core/tenancy.py`: ContextVar + `TenantManager` (فلترة تلقائية) + `tenant_context` + `TenantMiddleware`.
- `apps/core/models.py`: `Tenant`, `TenantScopedModel` (إسناد تلقائي للمستأجر), `Account` (أنواع: مكتب صغير/وسيط/محل/ذاتي/أرباح), `JournalEntry`/`JournalLine` (Decimal 18,4 + قيد DB يمنع سطراً صفرياً/سالباً + حذف يرمي خطأ), `AuditLog`.
- `apps/core/services.py`: `post_entry` (توازن لكل عملة، Decimal حصراً، حسابات نفس المستأجر، ذرّي) و`reverse_entry` (مرآة + وسم + منع العكس المزدوج).
- `apps/accounts/models.py`: مستخدم مخصص (`AUTH_USER_MODEL`) بدور (admin/big_office/small_office) + مستأجر + كود مكتب + حقول واتساب + حظر، مع تحقق: الأدمن بلا مستأجر والمكاتب بمستأجر إلزامي.
- `apps/core/permissions.py`: صلاحيات DRF للأدوار الثلاثة.

**Frontend:**
- `globals.css`: طبقة التوكِنز الكاملة (تدرّج العلامة 50-900، ذهبي، دلالية، pos/neg، محايدات، ظلال، زوايا) للوضعين عبر `@theme`.
- `components/ui/`: Button (4 variants × 3 sizes)، Badge (6 حالات الحركة بأسماء مركزية)، Card، Input، Select، Table (تمرير أفقي آمن)، StatCard (بدلالة pos/neg/profit)، EmptyState، Skeleton، Modal (Esc + وصولية)، Tabs — تصدير مركزي واحد.
- `lib/`: `cn`، `format` (formatMoney/balanceTone/formatDateTime — كل عرض مالي يمرّ منها)، `api` (عميل موحّد + ApiError)، `i18n/ar` (كل النصوص مركزية).
- صفحة `/design` (معرض المكوّنات) + PWA manifest + أيقونة العلامة.

## المرحلة 2 — المصادقة والهوية (Auth & Identity) 🔑

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** دخول موحّد + تذكّرني + استعادة كلمة المرور + الأكواد الفريدة + توجيه حسب الدور + تسجيل ذاتي معطّل.

### ما أُنجز

**Backend (`apps/accounts`):**
- **دخول موحّد JWT** (`/api/auth/login/`): يضيف للتوكن claims الدور والمستأجر وكود المكتب، يمنع المحظورين والمستأجرين الموقوفين، ويعيد بيانات المستخدم.
- **تذكّرني:** يرفع عمر refresh من يوم إلى 30 يوماً.
- **فرض الحظر على كل طلب** (`BlockAwareJWTAuthentication`) حتى مع توكن صالح — مضبوط افتراضياً في DRF.
- `/me/` و`/refresh/` و`/change-password/` (بالتحقق من الحالية).
- **استعادة هرمية** (`/reset-password/`): الكبير ← صغار مستأجره فقط؛ الأدمن ← الكبار فقط (لا علاقة له بالصغار)؛ الصغير ← لا أحد. كل استعادة تُسجَّل في AuditLog.
- **الأكواد الفريدة** (`services.py`): `BIGnnn` للكبار، و`BIGnnn-SMLmmm` للصغار (الكود يحمل هوية الكبير — عزل)، مع `create_big_office`/`create_small_office` ذرّيتين.
- **التسجيل الذاتي** (`/register/`): خلف مفتاح `PlatformSettings.self_registration_enabled` (معطّل افتراضياً)؛ عند التفعيل ينشئ مستأجراً **موقوفاً** بانتظار تفعيل الأدمن؛ يتطلب الموافقة على الشروط وتطابق كلمتي المرور.
- نموذج `PlatformSettings` (صف واحد): الوضع المجاني + مفتاح التسجيل.

**Frontend:**
- صفحة `/login` بالمكوّنات المركزية: تذكّرني، «نسيت كلمة المرور؟» (نافذة تشرح الاستعادة الهرمية)، رسائل خطأ واضحة.
- `lib/auth.ts`: جلسة مركزية (تذكّرني → localStorage، وإلا sessionStorage) + `roleHome`.
- `RoleGuard`: يحمي الصفحات ويعيد كل دور لواجهته + زر خروج.
- ثلاث صفحات محمية (`/admin`، `/office`، `/small`) والجذر يوجّه تلقائياً.

## المرحلة 3 — وحدة الأدمن (Admin Module) 👑

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** إدارة المكاتب الكبيرة + الباقات + الاشتراكات (تفعيل يدوي) + مفتاح الوضع المجاني + إحصاءات غير مالية + بث + تدقيق.

### ما أُنجز

**Backend (`apps/admin_panel`):**
- **الباقات:** حدّان (مكاتب + حركات) + سعر + مدة؛ «الحذف» = تعطيل فقط (اتساقاً مع لا-حذف).
- **الاشتراكات:** المكتب يطلب → دفع يدوي خارج النظام → الأدمن يفعّل (يحسب الانتهاء) أو يرفض؛ منع طلبين معلّقين.
- **قاعدة الترحيل (المشهد 1):** `can_create_small_office` — الوضع المجاني مفتوح؛ المدفوع يحتسب فقط المكاتب المُنشأة **بعد** تفعيل الاشتراك.
- **إدارة المكاتب الكبيرة:** عرض (بلا أي حقل مالي — مفحوص بالاختبار)، فتح بكود مولّد، تعديل، **حظر/تفعيل يقطع وصول كل مستخدمي المستأجر فوراً** حتى مع توكن صالح (فُرض في طبقة المصادقة).
- **إعدادات المنصة:** مفتاحا الوضع المجاني والتسجيل الذاتي (GET/PATCH).
- **الإحصاءات:** أرقام مجرّدة فقط (مكاتب/صغار/طلبات معلّقة/تنتهي قريباً/عدد حركات).
- **البث:** تنبيهات الأدمن → المكاتب الكبيرة فقط، ونقطة قراءة للمكتب الكبير.
- **التدقيق:** كل فعل أدمن يُسجَّل + نقطة عرض آخر 100 سجل.
- جانب المكتب الكبير: عرض الباقات المتاحة واشتراكاته + طلب باقة.

**Frontend (لوحة `/admin` كاملة):**
- `Shell` مركزي (شريط جانبي RTL + ترويسة) قابل لإعادة الاستخدام لكل الأدوار.
- `authedApi` مركزي (توكن تلقائي + 401 → خروج).
- 6 صفحات: الرئيسية (إحصاءات)، المكاتب (جدول + إنشاء + حظر/تفعيل)، الباقات (جدول + إنشاء)، الاشتراكات (تبويبا معلّقة/أرشيف + تفعيل/رفض)، التنبيهات (بث + قائمة)، الإعدادات (مفتاحان).

## المرحلة 4 — النواة المحاسبية (Accounting Core) ⭐

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** العملات + صناديق الوسطاء والمحل + حسابات الصغار + الحدود السالبة + التسويات + عكس القيد — بأرصدة صحيحة تُختبَر آلياً.

### ما أُنجز

**تصحيحان جوهريان اكتشفتهما هذه المرحلة:**
1. **ضبط اصطلاح الأرصدة على السرد:** `balance = مدين − دائن`. صندوق: موجب = رصيدنا فيه؛ **الإيداع يزيده وتمرير الحركة ينقصه** (حرفياً كالمشهدين 2 و5)؛ صغير: موجب = عليه؛ الربح دخل دائن يُعرض معكوساً. حُدّثت الوثيقة 02 §0 و§4 واختبارات المرحلة 1، مع اختبار السيناريو السردي: إيداع 2000 − حركة 1010 = **990** ✓.
2. **🔴 ثغرة عزل حقيقية اكتشفتها الاختبارات:** مصادقة JWT تحدث بعد Django middleware، فسياق المستأجر لم يكن يُضبط عبر الـ API (مستأجر رأى عملات غيره!). **الإصلاح:** ضبط السياق في `BlockAwareJWTAuthentication.get_user` (والـ middleware للتنظيف). اختبارا العزل عبر API يثبتان الإصلاح.

**تطبيق `apps/boxes`:**
- **Currency**: عملات لكل مستأجر يديرها الكبير (uniq لكل مستأجر).
- **IntermediaryBox**: اسم + رقم + عملات M2M (الجزء 12) — حساب دفتر أستاذ لكل (صندوق × عملة) يُنشأ عند أول حاجة.
- **SmallOfficeAccount / ShopCashAccount / FeesProfit**: توفير حسابات تلقائي لكل عملة.
- **CreditLimit** (الجزء 5): حد سالب لكل (صغير × عملة) + `check_credit_limit` بالرياضيات الصحيحة، و**التعزيز يفتح المجال** (مختبَر).
- **التسويات (المشهد 5):** `deposit_to_box` (مدين الصندوق/دائن الصغير) و`withdraw_from_box` (العكس) — عبر محرك القيود حصراً.
- **API كامل للكبير:** عملات CRUD، صناديق (+أرصدة لكل عملة +كشف +اعتماد +سحب)، حدود، صندوق المحل (أرصدة+كشف)، **عكس قيد** لأي قيد ضمن مستأجره.
- **API للصغير:** `/api/small/balances/` — له/عليه/الصافي لكل عملة (الجزء 3-د).
- كل فعل مالي في سجل التدقيق.

## المرحلة 5 — الحركات (Transactions) 🔄

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن:** الدورة الكاملة للحركة (إنشاء→قبول/رفض→دفع/تسليم→تعديل/عكس) بواجهات الطرفين وقيود دقيقة.

### ما أُنجز

**Backend (`apps/transactions`):**
- **النموذج الكامل:** مرجع فريد `HW-BIGnnn-nnnnnn` مرتبط بكود المكتب، مرسِل/مستفيد/وجهة (نص حر)، عملتا قبض/تسليم + سعر صرف مثبّت + مبلغ مسلَّم، أجور (رأس مال/مستحقة)، 3 حالات مستقلة، روابط قيود القبول والدفع.
- **قرار تقني موثّق:** الأجور **بالعملة المقبوضة** (حسم سؤال الدورة §8).
- **قيد القبول أحادي العملة** = المشهد 2 حرفياً؛ **ثنائي العملة عبر حسابات مقاصة صرف** لكل عملة → متوازن لكل عملة مع مركز صرف قابل للتدقيق (نوع حساب جديد FX_CLEARING).
- **فحوص قبل القبول:** اكتمال الأجور + سعر الصرف إن اختلفت + **الحد السالب** (يمنع برسالة «تعزيز الرصيد» والحركة تبقى معلّقة).
- مدفوعة (§4-ب): نقد للمحل ويصفّي دين الصغير. تسليم: حالة فقط. رفض: بلا قيود. **عكس كامل** (يعكس الدفع ثم القبول). **تعديل** عبر عكس+إعادة ترحيل.
- **حد حركات الباقة** مع الترحيل (المشهد 1) + ربط عدّاد الأدمن.
- قوائم بفلتر موحّد (حالات/عملة/تاريخ/بحث/منشئ): جارية/سجل للكبير، وسجل خاص للصغير. **الكبير يُنشئ لنفسه من نفس النقاط** (المشهد 3).

**Frontend:**
- **الصغير:** رئيسية (صناديقه لكل عملة + آخر الحركات)، **إرسال حركة** (تنبيه ثنائية العملة، وبعد الحفظ **زر واتساب** ينسخ النص المُقولب ويفتح رابط مجموعته — قالب مركزي في `lib/whatsapp.ts`)، سجل بفلتر.
- **الكبير:** رئيسية (عدّاد الجارية)، **الحركات الجارية** بنافذة معالجة كاملة (صناديق مؤهّلة بعملة التسليم فقط + أجور + سعر صرف إلزامي عند الاختلاف + **عرض الربح حياً** + قبول معطّل حتى الاكتمال)، **سجل** بأزرار مدفوعة/تسليم/عكس.

## المرحلة 8 — الوقت الحقيقي والإشعارات (Real-time & Notifications) ⚡

### ما أُنجز

**Backend (`apps/notifications`):**

- **بث الكبير → مكاتبه** (`OfficeBroadcast`): كان ديناً من المرحلة 3 — أُنجز الآن مع تفريع إشعار لكل عضو غير محظور.
- نقاط: قائمة الإشعارات + غير المقروء، قراءة الكل/واحد، بث الكبير + قراءة الصغير.

**Frontend:**
- `lib/ws.ts` مركزي: اتصال واحد، إعادة اتصال تلقائية، بثّ داخلي بحدث `hawalat:ws` موحّد.

- **تحديث لحظي**: الجارية للكبير تتحدّث عند وصول حركة؛ رئيسية الصغير وصناديقه عند تغيّر الأرصدة؛ تنبيهات الصغير عند البث.

## المرحلة 9 — تكامل الواتساب (WhatsApp Integration) 🟢

- **الحالة:** ✅ **مقبولة ومغلقة** — 2026-08-07
- **الهدف المعلن (الجزء 17 §6):** رابط افتراضياً + بوت اختياري بمفتاح: مفعّل → تلقائي؛ مطفأ → يدوي.

### ما أُنجز

**Backend (`apps/whatsapp`):**
- `WhatsAppSettings` لكل مستأجر: **مفتاح البوت** + عنوان بوابة + رمز — يتحكم بها الكبير حصراً.
- **Outbox** (`WhatsAppMessage`): كل رسالة بحالة (قيد/أُرسلت/فشلت) + محاولات + آخر خطأ.

- خدمة `queue_message`: تقرر الوضع — بوت جاهز + معرّف مجموعة → طابور؛ وإلا None (يدوي).
- نقاط: حالة البوت للمستخدم، إرسال (الصغير لمجموعته حصراً/الكبير لأعضائه حصراً)، إعدادات الكبير، سجل الصادر.
- **ربط تلقائي**: إنشاء حركة والبوت مفعّل → رسالة الحركة تُرسل فوراً لمجموعة المُنشئ.
- حقل `whatsapp_chat_id` في ملف العضو (اختياري — يلزم للبوت فقط).

**Frontend:**
- صفحة `/office/settings`: مفتاح البوت + البوابة + شارة جاهزية + **سجل رسائل البوت**.
- **زر الإرسال الذكي** في إرسال الحركة: بوت جاهز → «🤖 إرسال عبر البوت» (فوري) مع **تحوّل تلقائي للرابط اليدوي عند فشل البوت**؛ وإلا الزر اليدوي المعتاد.
- حقل معرّف مجموعة البوت في إنشاء العضو.
